  - [Velda] Are there priority issues, how do you look for something to work on.
    - [Ryan] One way is to look based on activity, if something hasn't been

      custom README, the `python` GitHub organisation does not have one
      currently.
- [Velda] Are there interesting issues you've reviewed before, so I can read
  through the comments on a review?
- [Ryan] Looking at issues. Start by going to issues, then look at
  [`label:docs`](https://github.com/python/cpython/issues?q=is%3Aissue+is%3Aopen+label%3Adocs).
  - One thing for me: I don't know what to respond to, so I often look at issues
    that don't have a ton of comments on them.
  - Starting on issue [#158681](https://github.com/python/cpython/issues/158681)
    as an example, I read through it.
  - Then after reading it, I'll often look at the user's account. If they're
    very new user, I'll add a welcome comment. If they're a core team member,
    it's possible I'll not know as much so I might not be able to offer helpful
    suggestions to their PR/Issue. This helps me select an issue/PR to focus on.
  - Moving on to the Pull Request: I look to see if it is a documentation
    change. I see if it's correct, and if it's helpful. I like to ask leading
    questions which, if it has an answer, will help increase the chance that the
    PR is going to be merged.
  - Sometimes if there's a concern about the person's interest in the issue,
    I'll immediately ask a question. This helps gauge their interest in actually
    improving their PR.
  - GitHub Views: might help add filters so you can filter for issues/PRs which
    have specifics you're interested in, be it issues not submitted by core
    team, PRs with a keyword, etc.
